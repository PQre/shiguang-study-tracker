# 提示词与迭代记录

本文件记录当前工作区这次实际开发的阶段和可复用提示词。它不冒充本人此前在 Trae 操作的聊天记录。截图均来自本次运行，演示数据明确标注。

公开仓库版本已移除姓名输入与图片个人署名，下面关于署名布局的条目仅记录早期迭代。当前导出行为以 Spec 和操作手册为准。下载的教材原文、个人资料和本地测试报告不随仓库发布。

## 任务来源

用户任务：根据训练营考核说明完成每日知识点分享和最终项目。阅读考核、教材首页、课程章节和项目实战要求后，采用推荐项目“学习打卡追踪器”。尚未收到本期专用项目任务文件。

## 可复用开发提示词

以下是按实施约束整理的复现提示词，不是伪造的原始聊天导出。

1. 需求：你是软件需求分析师。为教材推荐的学习打卡追踪器编写单用户Spec，定义计划、日期、打卡、统计和分享图片导出的验收条件。不得自动生成已完成学习记录。
2. 设计：你是后端架构师。技术栈FastAPI、SQLite、Vue。给出分层职责、数据库外键与唯一索引、API请求与错误码。明确同一日跨计划统计去重。
3. 实现：依据Spec先实现API，再实现Vue页面。校验未来日期、计划外日期和重复打卡。前后端使用同一份契约，记录需要持久化。
4. 测试：对重复日期、空内容、无效日期、跨计划统计、CSV公式字符、删除保护和重启后的持久化写业务测试，使用独立临时库。
5. 审查：指出需求、设计和实现的不一致，给出触发输入与修复证据。未测试项明确标记，不写成已通过。
6. 交付：按项目实战要求整理源码、设计、测试、操作手册、提示词、迭代截图和PPT，保留姓名、期次与个人体会的实际补充需求。
