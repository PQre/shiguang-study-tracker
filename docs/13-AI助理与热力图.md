# 学习热力图与AI助理

## 已增加的功能

- 学习概览的日期格按分钟数连续加深，0分钟为空白底色，120分钟及以上达到最深色。鼠标停留可查看日期与时长。
- 左下角21格展示近21天实际记录，沿用当前统计范围。同一天多个计划的分钟数相加。
- 右下角“AI助理”提供复习对话、识别录入和设置。
- “记录学习”表单也提供“识别录入”入口。截图、照片与文字可以一起提交，草稿支持修改和勾选字段，只填表单、不自动保存。

## 配置模型接口

1. 在项目根目录复制 `.env.example` 为 `.env`。`.env` 已被Git忽略，不放进网页目录或公开仓库。
2. 填写以下三项：

```dotenv
TRACKER_AI_BASE_URL=https://你的模型接口地址/v1
TRACKER_AI_MODEL=支持图片输入的模型名称
TRACKER_AI_API_KEY=你的模型密钥
```

接口使用兼容 OpenAI Chat Completions 的格式。地址可以填 `/v1` 基址，也可以填完整 `/chat/completions` 路径。文字模型可用于复习对话；图片识别需要模型支持图片输入。

默认请求 `response_format: {"type":"json_object"}`。供应商不支持时将 `TRACKER_AI_RESPONSE_FORMAT=none`；支持严格JSON Schema时可以设为 `json_schema`。所有模式都会再验证结果的字段、长度、整数时长和日期。

3. 本机使用完整网页版，运行：

```powershell
python run.py --demo
```

打开 `http://127.0.0.1:8000`。助理设置里的“AI服务地址”可以留空，直接使用同一个FastAPI服务。API密钥由后端读取，网页不会接收密钥。

## 让GitHub Pages连接AI

GitHub Pages仍托管静态页面。AI调用需要单独运行本项目后端；把模型密钥配置在GitHub仓库或Pages构建环境，不能代替一个运行中的AI服务。

在部署AI服务的机器上设置：

```dotenv
TRACKER_AI_ACCESS_TOKEN=你自行设置的随机访问口令
TRACKER_AI_ALLOWED_ORIGINS=https://pqre.github.io
```

可用 `python -c "import secrets; print(secrets.token_urlsafe(32))"` 在本机生成口令。此口令与供应商的API密钥不同，只用于控制对拾光AI服务的访问。

运行独立AI服务：

```powershell
python run.py --ai-only --host 0.0.0.0 --port 8000
```

用部署平台或反向代理为该服务提供HTTPS。`--ai-only`只开放AI接口，不暴露本地打卡数据库API。远程调用没有配置访问口令时会拒绝处理。跨域权限只对AI接口生效，原有记录写入仍保持同源保护。

随后打开GitHub页面，点击“AI助理 → 设置”：

- AI服务地址：填部署后的拾光服务地址，如 `https://你的服务域名`，不要填模型供应商的 `/v1` 地址。
- 服务访问口令：填后端设置的访问口令。
- 点击“保存地址并连接”。地址保存在浏览器；口令只在当前页面内存中保留，刷新后需重填。

用户数据仍在当前浏览器或完整网页版数据库。只有发送问题时匹配到的记录、近期对话，以及主动识别的图片文字会传给配置的模型服务。

## 如何检索记录进行复习

助理打开时读取全部打卡记录，独立于概览的临时筛选。用户可以另外选择复习计划。发送问题时重新读取记录，以避免引用已删除内容。

当前检索在本地按主题、学习收获和下一步匹配关键词，选取最多6条。普通“回顾最近学习”会选最近记录，具体关键词无匹配时不会伪造结果。跟进问题可保留上一轮仍然有效的引用。回答下方展示本次交给模型的记录，便于核对。

这是关键词检索结合模型回答，未部署向量数据库或本地大模型。AI应区分原记录内容与补充解释。它没有修改或删除打卡的工具。

## 图片与文本录入

支持PNG、JPEG、WebP，一次最多3张，原图每张不超过12MB。浏览器缩放到最长边2048像素并重新编码，每张发送图片不超过2MB。也可向学习材料文本框粘贴截图。

模型只提取材料中的信息。不能确定的日期、分钟或收获留空，不把状态栏时间当作学习时长。不确定项显示在草稿下方。用户选择应用哪些字段，系统检查日期范围，保留原计划和分享上传状态；确认后仍需点击原表单的“保存”。同计划同日唯一等规则继续生效。

图片和待识别文字只保留在当前页面内存，不写入打卡数据库。AI对话同样不落库。

## 测试与当前验证范围

后端包含AI鉴权、CORS、上传边界、模型输出校验、未知字段、引用及原有业务的自动化测试。新增 `node scripts/test_assistant.cjs` 检查热力图、检索范围以及应用草稿不自动保存、不修改分享状态。

```powershell
python run_tests.py
python scripts/build_demo.py
node scripts/test_demo.cjs
node scripts/test_assistant.cjs
```

自动化与界面联调使用模拟模型响应，不调用真实付费接口。使用自己的模型配置后，还需验证该供应商的联网、图片识别效果与额度。接入失败会显示错误，不回退成伪造的AI识别或回答。

## 接口

- `GET /api/ai/status`：是否配置、是否需要访问口令，不返回密钥或供应商地址。
- `POST /api/ai/extract`：`text`与`images`，返回可为空的日期、分钟、主题、收获、下一步以及不确定项。
- `POST /api/ai/chat`：问题、最多6条检索记录、最多8条近期对话，返回回答和资料来源。

单个请求最多9MiB，模型响应最多256KiB。每个来源地址每分钟最多12次请求，同时最多处理2次模型调用。此限制为单进程内限制，正式多人部署应在网关增加统一额度与用户权限。

协议参考：[图片输入](https://developers.openai.com/api/docs/guides/images-vision)、[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)、[服务端认证](https://developers.openai.com/api/reference/overview)。
